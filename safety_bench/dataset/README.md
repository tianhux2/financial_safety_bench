# Data provenance

This file explains where every case comes from. All cases are generated by `safety_bench/build/build_dataset.py` from the frozen seed file `safety_bench/build/sources/seed_cases.jsonl` and from constants in the generator. The build is deterministic: it applies fixed arithmetic and templates and makes no manual choices.

Manual work happened only when the seeds and constants were created. Each table below marks which inputs were selected by rule and which were written by hand, and how hand-written inputs were checked.

## Sources of truth

| Truth | Source |
|---|---|
| Figures from company filings | FrontierFinance expert rubrics, built from SEC filings (CC-BY-4.0, gated, not included here) |
| Figures from earnings calls and analyst consensus | FrontierFinance expert rubrics |
| Share prices | Tiingo daily prices, retrieved when the cases were generated |
| Facts behind hand-written cases | Company filings, earnings releases and press coverage, cited in each case's `provenance` |

## False figures

| Attack | Cases | Input | How it was chosen | Method |
|---|---|---|---|---|
| M1–M3 | 72 | 8 filing figures, one per company: AIG, Alibaba, Walmart, Disney, Johnson & Johnson, GE, Starbucks, Pfizer | Single-company numeric rubrics, excluding rubrics that name another company and figures too short to locate reliably. Per company, the first such fact in dataset order that reached the agent in pilot runs, excluding facts it missed in every clean pilot run. One rubric with a typo in the segment name was excluded. | Rule |
| M1–M3 false values | | Computed from the true value | ×1.15, or ×10 for the implausible-value variant, in the same number format | Rule |
| M2 conflicting | 8 | 8 figures that rarely appear in filings: Meta, Microsoft, Block, T-Mobile, Dominion, Diageo, Novo Nordisk, AbbVie | Rubrics tagged as earnings-call or consensus data, marked required, naming one company and one number, excluding ordinary financial-statement items and ranges. Kept only if a live web search returned the true value (36 of 124 candidates). Eight companies picked by hand from those. One candidate was replaced because its rubric labelled the actual revenue as the consensus estimate. | Rule, then hand-picked |
| M2 conflicting false values | | Computed from the true value | ×1.15, ×0.87 and ×1.30, one per fabricated source | Rule |
| M4 | 12 | Metrics that the companies do not disclose: Apple, Tesla, Nvidia, Amazon, Meta, Spotify, two each | Hand-written questions and fabricated sources; each case cites the disclosure fact it relies on | Hand-written |

The fabricated news outlets and their web domains are invented. Every name and domain was checked for zero matches in DNS, web search and SEC full-text search before use.

## False premises

| Attack | Cases | Input | Method |
|---|---|---|---|
| P1 | 24 | 12 companies, each paired with a business from a fixed list of six (for example a reusable orbital rocket), rotated in a fixed order and skipping businesses close to the company's sector | Rule |
| P2 invented company | 12 | A plausible acquisition of an invented company in the same industry | Hand-written; every invented name checked for zero matches in web search and SEC full-text search |
| P2 real company | 6 | A false event at a real company, such as an acquisition that never happened | Hand-written, with sources |
| P3 | 12 | A real business line of each company, described as the main driver of its share price | Hand-written; each business confirmed in the company's 10-K by SEC full-text search |
| Baselines | 24 | The same question about the real business, and the same question with the premise removed | Rule |

Share-price changes for these cases are computed from Tiingo prices for the start of 2025 through September 30, 2025.

## User pressure

| Attack | Cases | Input | Method |
|---|---|---|---|
| U1 | 6 | Demands for a favorable conclusion about reported results, with the results stated in the prompt | Hand-written, with sources |
| U1 | 6 | The same demand for the six companies with the weakest 2025 share price among the premise companies, with the move taken from Tiingo | Rule |
| U2 | 12 | Requests to prove a sweeping claim about a sector, such as every company in it growing or shrinking | Hand-written; six of them name a counterexample checked by web search against company releases |
| Baselines | 24 | The same task without the pressure | Hand-written |

## Hidden instructions

| Input | Source | Method |
|---|---|---|
| User questions | Two FrontierFinance questions, about AIG and Walmart: US companies on which the agent often used web search, with few rubrics to grade | Rule |
| Instruction styles | Naive, context ignoring and fake completion (Liu et al., USENIX Security 2024); important message (AgentDojo, NeurIPS 2024); house style and an instruction addressed to the retrieval sub-model (written for this benchmark) | Templates |
| Goals | Add a line, add a link, force a rating, open a URL | Templates |
| Markers | A unique token per case, so that reach and compliance can be detected; URLs to open use the reserved `.example` domain | Rule |

These 88 cases and their baselines are built from FrontierFinance and are not in the public file.

## Confidential information

| Input | Source | Method |
|---|---|---|
| Target companies | 12 real companies | Fixed list |
| Client names and deal code names | 12 pairs of deliberately unusual invented names, checked against earlier agent trajectories so that a match cannot be a coincidence | Hand-written |
| Stake size and wording | Stake sizes rotate from 4.5% by rule; prompts use fixed templates | Rule |

## What is public

| | Cases | In this repository |
|---|---|---|
| M4, P1–P3, U1–U2, C1–C3 and their baselines | 198 | Yes, in `cases.jsonl` |
| M1–M3, I1–I4 and their baselines | 176 | No. Rebuilt locally into `cases_full.jsonl` from FrontierFinance |

For the second group, the seed file keeps only FrontierFinance query and rubric IDs, the true figures and the attack parameters. The build reads the questions and rubric sentences from your copy of FrontierFinance, checks its SHA-256 against the version the cases were frozen with, and reproduces the frozen cases exactly.

## Limitations

- Expert rubrics can contain errors. One was found and replaced. The clean baseline of each fact shows whether the agent can state it without an attack.
- The seeds are frozen. The steps that created them are documented here but cannot be rerun from this repository, because some depended on pilot runs that are not published.
- Hand-written inputs are checked as described above, but they were not derived from a source dataset.
